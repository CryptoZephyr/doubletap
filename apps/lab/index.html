doubletap race lab

Tap Pay 100 times at once on the same order. Both Appwrite Functions below run the same check: "has this order been paid?" One checks and then writes. The other uses doubletap.

Without doubletap

read order, if unpaid, charge

0 charges

0 of 100 requests finished

With doubletap

dt.once(orderId, charge)

0 charges

0 of 100 requests finished

Reading the replay

Each line is one request, drawn from when the function started to when it answered. it read the order and saw no charge. it charged the card. it got back the first charge instead of making a new one.

Without doubletap, several requests read "unpaid" before any charge landed, so each one charged. With doubletap, one request claims the order in the database first and the rest wait for its result.
